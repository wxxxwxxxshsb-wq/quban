# Privacy 出错了怎么查（3 步）

## 1. 拿到「错误码」
- 页面提示里带「错误码 xxxxxxxx」时，把这 8 位码发给我。
- 没有错误码也没关系，页面里的 JS 报错会自动上报，不用用户操作。

## 2. 在 Render 日志里搜
Render 服务 → **Logs**，在搜索框粘贴错误码，会同时看到：
- 这次请求的接口、状态码、耗时、用户（一行）
- 完整的报错原因和出错位置（`stack`）

日志每行都是 JSON，`level` 为 `error` 的是出错，`warn` 是请求被拒绝或很慢。
只想看所有错误：搜索 `"level":"error"`。

## 3. 看整体健康状况
- `https://你的网址/healthz`：打开显示 `ok:true` 就说明服务活着（Render 也用它自动检测）。
- `https://你的网址/api/diag?key=你的DIAG_KEY`：运行时间、内存、数据目录能不能写、用户数、AI 用的哪个、**最近 50 条错误**。

先在 Render → Environment 新增 `DIAG_KEY`（随便设一个长一点的口令），不设置这个接口就是关闭的。

## 启动时的自检提示
每次启动，日志开头会写「启动自检」：
- 数据目录不可写 → 账号存不下来，先修这个。
- 在 Render 上没设 `DATA_DIR` → 账号和消息重启会丢。
- 没有 AI 密钥 → 小伴不能回答。
- 邮件或短信验证码报“服务尚未配置” → 按「验证码配置.md」把服务商变量添加到 Render → Environment，然后重新部署。

## 本地运行
报错同时会写入 `data/errors.log`（超过 1MB 自动换新文件）。
